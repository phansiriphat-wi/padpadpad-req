# แผนงานเทคนิค: สมัครเข้าร่วมค่าย (Camp Enroll)

## 1. สรุปแนวทาง
- ฟีเจอร์นี้ให้นักศึกษาสามารถเลือกค่ายที่เปิดรับสมัคร กรอกข้อมูลที่จำเป็น แนบเอกสาร และส่งใบสมัครเพื่อยืนยันการเข้าร่วมตาม FR-ENR-01 ถึง FR-ENR-07
- ผู้ใช้หลักคือ นักศึกษา และระบบจะต้องตรวจสอบความครบถ้วนและรูปแบบของข้อมูลก่อนบันทึกข้อมูลสมัครตาม CON-ENR-03, CON-ENR-04, IF-ENR-01 และ IF-ENR-02
- เมื่อข้อมูลหรือเอกสารยังไม่ครบ ระบบจะเปิดโหมด Draft เพื่อให้ผู้สมัครกลับมาทำต่อได้ และไม่บันทึกใบสมัครที่ยังไม่สมบูรณ์ตาม ASM-09 และ NFR-REL-01
- เมื่อข้อมูลครบถ้วนแล้ว ระบบจะบันทึกใบสมัครและกำหนดสถานะเป็น “รอตรวจสอบ” พร้อมให้ผู้สมัครสามารถตรวจสอบสถานะได้ตาม AC-ENR-04 และ AC-ENR-05
- การพัฒนาโดยรวมจะเน้นการ validate แบบละเอียดก่อนบันทึกข้อมูลและเอกสาร เพื่อตรงกับเงื่อนไขของค่ายที่กำหนดเองใน ASM-07

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
| --- | --- | --- |
| React (Vite) สำหรับส่วนหน้า | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้แสดงรายการค่าย ฟอร์มสมัคร และหน้าแสดงสถานะใบสมัครของนักศึกษา |
| Python FastAPI สำหรับส่วนหลังบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้จัดการ validate ข้อมูลสมัคร เอกสาร และการบันทึกใบสมัคร |
| PostgreSQL | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บตารางค่าย ใบสมัคร ข้อมูล Draft และเอกสารที่แนบเข้ามา |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ FR |
| --- | --- | --- |
| Camp | camp_id, name, status, open_date, close_date, created_at | FR-ENR-01, CON-ENR-01, ASM-02 |
| Applicant | applicant_id, user_id, full_name, created_at | FR-ENR-02, CON-ENR-02, ASM-01 |
| Application | application_id, applicant_id, camp_id, status, submitted_at, created_at, updated_at | FR-ENR-06, FR-ENR-07, ASM-04, ASM-05 |
| ApplicationDraft | draft_id, application_id, form_data_json, last_saved_at | FR-ENR-02, ASM-09 |
| ApplicationDocument | document_id, application_id, document_type, file_name, file_url, validation_status, validated_at | FR-ENR-04, FR-ENR-05, ASM-07, ASM-08 |
| ValidationError | error_id, application_id, field_name, error_message, created_at | FR-ENR-03, FR-ENR-05, NFR-USE-01 |

หมายเหตุ: ระบบจะไม่มีฟิลด์เก็บข้อมูลประเภทบัตรประจำตัวหรือข้อมูลที่ไม่ระบุใน spec เพื่อให้ตรงกับข้อจำกัดของ NFR-SEC-01 และไม่มีการเก็บข้อมูลเอกสารที่ไม่ผ่าน validate ตาม NFR-REL-01

## 4. API / หน้าจอ

- GET /camps/open — แสดงรายการค่ายที่เปิดรับสมัคร พร้อมสถานะค่ายที่เปิดอยู่ — รองรับ FR-ENR-01, CON-ENR-01
- GET /applications/{campId}/draft — โหลดฟอร์มสมัครแบบ Draft ของนักศึกษาคนปัจจุบัน — รองรับ FR-ENR-02, ASM-09
- POST /applications/validate — ตรวจสอบความครบถ้วนของข้อมูลสมัครและเอกสารที่แนบ — รองรับ FR-ENR-03, FR-ENR-05, IF-ENR-01, IF-ENR-02, NFR-USE-01
- POST /applications/submit — ส่งใบสมัครพร้อมบันทึกสถานะ “รอตรวจสอบ” — รองรับ FR-ENR-06, FR-ENR-07, AC-ENR-04
- GET /applications/{applicationId} — แสดงข้อมูลใบสมัครและสถานะของนักศึกษา — รองรับ NFR-DATA-01, AC-ENR-05, ASM-10
- GET /applications/me — แสดงรายการใบสมัครของนักศึกษาในระบบ — รองรับ NFR-SEC-01, ASM-10

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
| --- | --- | --- |
| CON-ENR-01 | หน้าแสดงค่ายและ API /camps/open จะเลือกเฉพาะค่ายที่เปิดรับสมัครเท่านั้น | ใช้แล้ว |
| CON-ENR-02 | ทุกหน้าและ API ของการสมัครจะต้องตรวจสอบ user session ก่อนเข้าถึงข้อมูล | ใช้แล้ว |
| CON-ENR-03 | POST /applications/validate และ POST /applications/submit จะตรวจสอบว่าข้อมูลสมัครครบถ้วนก่อนบันทึก | ใช้แล้ว |
| CON-ENR-04 | Validation layer สำหรับเอกสารจะตรวจสอบรูปแบบและความครบถ้วนก่อนบันทึก | ใช้แล้ว |
| IF-ENR-01 | ขั้นตอน validate และ submit จะหยุดทันทีเมื่อพบข้อมูลไม่ครบถ้วนก่อนพยายามบันทึก | ใช้แล้ว |
| IF-ENR-02 | ขั้นตอน validate เอกสารจะทำก่อนบันทึกใบสมัครเพื่อป้องกันการบันทึกข้อมูลที่ไม่สมบูรณ์ | ใช้แล้ว |

## 7. ลำดับงาน

1. สร้างโครงสร้างข้อมูลพื้นฐานสำหรับ Camp, Application, ApplicationDraft และ ApplicationDocument — เกี่ยวข้องกับ FR-ENR-01, FR-ENR-02, FR-ENR-04, FR-ENR-06, FR-ENR-07
2. สร้างหน้าแสดงค่ายที่เปิดรับสมัครและจำกัดเฉพาะค่ายที่มีสถานะ “เปิดรับสมัคร” เท่านั้น — เกี่ยวข้องกับ FR-ENR-01, CON-ENR-01, ASM-02
3. สร้างฟอร์มสมัครพร้อมการบันทึก Draft เพื่อให้กลับมาทำต่อได้ — เกี่ยวข้องกับ FR-ENR-02, ASM-09
4. เพิ่มระบบ validate ข้อมูลสมัครเพื่อให้แจ้งและระบุช่องที่ต้องแก้ไขเมื่อข้อมูลไม่ครบ — เกี่ยวข้องกับ FR-ENR-03, AC-ENR-02, NFR-USE-01, IF-ENR-01
5. เพิ่มระบบ validate เอกสารเพื่อให้ตรวจความครบถ้วนและรูปแบบก่อนบันทึกใบสมัคร — เกี่ยวข้องกับ FR-ENR-04, FR-ENR-05, AC-ENR-03, CON-ENR-04, IF-ENR-02, ASM-07, ASM-08
6. เพิ่ม workflow ยืนยันการส่งใบสมัครและบันทึก Application พร้อมสถานะ “รอตรวจสอบ” — เกี่ยวข้องกับ FR-ENR-06, FR-ENR-07, AC-ENR-04, ASM-04
7. สร้างหน้าแสดงข้อมูลใบสมัครและสถานะของนักศึกษา พร้อมการแจ้งเตือนเมื่อลดสถานะเป็นอนุมัติ — เกี่ยวข้องกับ NFR-DATA-01, AC-ENR-05, ASM-10
8. เพิ่มการตรวจสอบสิทธิ์การเข้าถึงข้อมูลและการเก็บข้อมูลแบบจำกัดเฉพาะผู้ใช้งานที่มีสิทธิ์ — เกี่ยวข้องกับ NFR-SEC-01, NFR-REL-01
9. ทดสอบความสอดคล้องกับทุก AC และตรวจ traceability กับ FR, NFR, CON, IF — เกี่ยวข้องกับ AC-ENR-01 ถึง AC-ENR-05

- รายละเอียดเชิงตัวเลขของประเภทไฟล์และขนาดไฟล์ยังไม่ได้กำหนดใน spec ตาม ASM-08 จึงยังไม่ทำการเชิงลึกต่อในแผนนี้
