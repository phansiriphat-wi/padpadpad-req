# Feature: จัดกลุ่มและฝ่ายงาน (Group Management)
Spec ID: SPEC-GRP-004 | Source: SRS v1.0 (FR-GRP) | Use case: UC-04
Owner: คณะกรรมการ | Status: Draft v2 | Updated: 2569-09-19

## Goal
คณะกรรมการสามารถจัดผู้เข้าร่วมค่ายที่ผ่านการคัดเลือกแล้วเข้าสังกัดกลุ่มหรือฝ่ายงานที่ต้องการ
ระบบบันทึกข้อมูลกลุ่ม/ฝ่ายของผู้เข้าร่วม เพื่อให้สามารถบริหารจัดการผู้เข้าร่วมและให้ผู้เข้าร่วมทราบกลุ่มหรือฝ่ายที่ตนสังกัด

## Scope
### In scope
- แสดงรายชื่อผู้เข้าร่วมค่ายที่ผ่านการคัดเลือกแล้ว
- เลือกผู้เข้าร่วมค่ายที่ต้องการจัดกลุ่มหรือฝ่าย
- เลือกกลุ่มหรือฝ่ายที่ต้องการมอบหมาย
- ยืนยันและบันทึกข้อมูลการจัดกลุ่มหรือฝ่าย
- แสดงกลุ่มหรือฝ่ายปัจจุบันของผู้เข้าร่วม
- รองรับการย้ายผู้เข้าร่วมไปยังกลุ่มหรือฝ่ายใหม่

### Out of scope
- การรับสมัครผู้เข้าร่วมค่าย
- การคัดเลือกผู้เข้าร่วมค่าย
- การจัดการข้อมูลกลุ่มหรือฝ่าย
- การมอบหมายหน้าที่ภายในฝ่าย
- การบันทึกการเข้าร่วมกิจกรรม

## Constraints
- CON-GRP-01 ต้องมีรายชื่อผู้เข้าร่วมค่ายที่ผ่านการคัดเลือกแล้วก่อนดำเนินการจัดกลุ่มหรือฝ่าย
- CON-GRP-02 การจัดกลุ่มหรือฝ่ายต้องดำเนินการโดยคณะกรรมการ
- CON-GRP-03 การเปลี่ยนกลุ่มหรือฝ่ายของผู้เข้าร่วมที่มีสังกัดอยู่แล้ว ต้องได้รับการยืนยันก่อนบันทึก
- IF-GRP-01 รายชื่อผู้เข้าร่วมที่แสดงต้องมาจากข้อมูลผู้เข้าร่วมที่ผ่านการคัดเลือกแล้ว
- IF-GRP-02 กลุ่มหรือฝ่ายที่สามารถเลือกได้ต้องเป็นข้อมูลกลุ่มหรือฝ่ายที่มีอยู่ในระบบ

## Requirements
- FR-GRP-01 ระบบต้องแสดงรายชื่อผู้เข้าร่วมค่ายที่ผ่านการคัดเลือกแล้ว และต้องระบุสถานะว่า “รอจัดกลุ่ม” หรือ “จัดกลุ่มแล้ว” <- UC-04 main flow ขั้น 2
- FR-GRP-02 ระบบต้องให้คณะกรรมการเลือกผู้เข้าร่วมค่ายที่ต้องการจัดกลุ่มหรือฝ่าย โดยผู้เข้าร่วมแต่ละคนต้องมีสังกัดได้เพียงหนึ่งกลุ่มหรือฝ่ายเท่านั้น <- UC-04 main flow ขั้น 3
- FR-GRP-03 ระบบต้องให้คณะกรรมการเลือกกลุ่มหรือฝ่ายที่ต้องการมอบหมายให้ผู้เข้าร่วม โดยผู้เข้าร่วมจะต้องอยู่ฝ่ายหรือกลุ่มใดฝ่ายหนึ่งเท่านั้น และคณะกรรมการจะต้องอยู่ฝ่ายหรือกลุ่มใดฝ่ายหนึ่งเท่านั้น ไม่อนุญาตให้มีกรณีที่อยู่ทั้งฝ่ายและกลุ่มพร้อมกัน <- UC-04 main flow ขั้น 4
- FR-GRP-04 เมื่อคณะกรรมการยืนยันการจัดกลุ่ม ระบบต้องบันทึกข้อมูลกลุ่มหรือฝ่ายของผู้เข้าร่วม และหากดำเนินการย้ายสังกัดสำเร็จ ระบบต้องแจ้งเตือนผู้เข้าร่วมทันที <- UC-04 main flow ขั้น 5-6
- FR-GRP-05 หากผู้เข้าร่วมถูกจัดกลุ่มหรือฝ่ายไว้แล้ว ระบบต้องแสดงกลุ่มหรือฝ่ายปัจจุบันพร้อมสถานะ “จัดกลุ่มแล้ว” <- UC-04 alternative flow 3a
- FR-GRP-06 หากผู้เข้าร่วมถูกจัดกลุ่มหรือฝ่ายไว้แล้วและคณะกรรมการต้องการเปลี่ยนกลุ่ม ระบบต้องแสดงหน้าต่างยืนยันที่มีข้อมูลผู้เข้าร่วม สังกัดเดิม สังกัดใหม่ และปุ่มยืนยัน/ยกเลิกก่อนบันทึก หากยังไม่เริ่มงานหรือประกาศงานไม่ได้นำไปใช้จนกว่าจะเริ่มหรือประกาศงานแล้ว ให้ไม่ต้องเก็บประวัติสังกัดเดิม แต่ถ้าเริ่มงานหรือประกาศงานไปแล้ว ให้เก็บประวัติสังกัดเดิมไว้เมื่อมีการย้าย <- UC-04 alternative flow 3a

## Quality Requirements
- NFR-USE-01 คณะกรรมการต้องสามารถจัดกลุ่มหรือฝ่ายของผู้เข้าร่วมได้ตามขั้นตอนที่กำหนด โดยไม่เกิดความสับสนในการเลือกกลุ่มหรือฝ่าย
- NFR-DATA-01 ข้อมูลกลุ่มหรือฝ่ายของผู้เข้าร่วมต้องถูกบันทึกอย่างถูกต้อง และสามารถเรียกดูข้อมูลกลุ่มหรือฝ่ายปัจจุบันได้
- NFR-SEC-01 เฉพาะคณะกรรมการเท่านั้นที่สามารถจัดหรือเปลี่ยนกลุ่มหรือฝ่ายของผู้เข้าร่วมได้

## Acceptance Criteria
- [ ]   AC-GRP-01 (FR-GRP-01, FR-GRP-02, FR-GRP-03)
        Given มีรายชื่อผู้เข้าร่วมที่ผ่านการคัดเลือกแล้วและยังไม่ได้จัดกลุ่ม
        When  คณะกรรมการเลือกผู้เข้าร่วมและระบุให้สังกัด "ฝ่ายสวัสดิการ"
        Then  ระบบต้องแสดงผู้เข้าร่วมและกลุ่ม/ฝ่ายที่เลือกก่อนการยืนยัน พร้อมระบุสถานะว่า "รอจัดกลุ่ม"
- [ ]   AC-GRP-02 (FR-GRP-04)
        Given คณะกรรมการเลือกผู้เข้าร่วมและระบุให้สังกัด "ฝ่ายสวัสดิการ"
        When  คณะกรรมการกดยืนยันการจัดกลุ่ม
        Then  ระบบต้องบันทึกข้อมูลการจัดสังกัดกลุ่มของผู้เข้าร่วมเป็น "ฝ่ายสวัสดิการ" เรียบร้อย และแจ้งเตือนผู้เข้าร่วมหลังการย้ายสังกัดสำเร็จ
- [ ]   AC-GRP-03 (FR-GRP-05)
        Given ผู้เข้าร่วมถูกจัดให้อยู่ใน "ฝ่ายสวัสดิการ" แล้ว
        When  คณะกรรมการเลือกผู้เข้าร่วมคนดังกล่าว
        Then  ระบบต้องแสดงกลุ่ม/ฝ่ายปัจจุบันเป็น "ฝ่ายสวัสดิการ" พร้อมสถานะ "จัดกลุ่มแล้ว"
- [ ]   AC-GRP-04 (FR-GRP-06)
        Given ผู้เข้าร่วมถูกจัดให้อยู่ใน "ฝ่ายสวัสดิการ" แล้ว
        When  คณะกรรมการเลือกเปลี่ยนเป็น "ฝ่ายสถานที่"
        Then  ระบบต้องแสดงหน้าต่างยืนยันที่มีข้อมูลผู้เข้าร่วม สังกัดเดิม สังกัดใหม่ และปุ่มยืนยัน/ยกเลิก ก่อนบันทึก หากงานเริ่มหรือประกาศไปแล้ว ต้องเก็บประวัติสังกัดเดิมไว้ และเมื่อตกลงย้าย ระบบต้องแจ้งเตือนผู้เข้าร่วม

## Assumptions & Open Questions
- ASM-01 ผู้เข้าร่วมที่สามารถจัดกลุ่มหรือฝ่ายได้ ต้องเป็นผู้ที่ผ่านการคัดเลือกแล้ว
- ASM-02 กลุ่มหรือฝ่ายที่ใช้จัดผู้เข้าร่วมมีข้อมูลอยู่ในระบบแล้ว
- ASM-03 ผู้เข้าร่วมหนึ่งคนมีสังกัดกลุ่มหรือฝ่ายหลักได้หนึ่งกลุ่มในขณะเดียวกัน
- ASM-04 การย้ายกลุ่มจะเปลี่ยนข้อมูลกลุ่ม/ฝ่ายปัจจุบันของผู้เข้าร่วม
- ASM-05 ผู้เข้าร่วมและคณะกรรมการแต่ละคนต้องมีสังกัดได้เพียงหนึ่งฝ่ายหรือหนึ่งกลุ่มเท่านั้น และไม่มีกรณีที่ต้องอยู่ทั้งฝ่ายและกลุ่มพร้อมกัน
- ASM-06 หากยังไม่ได้เริ่มงานหรือประกาศงาน ระบบไม่จำเป็นต้องเก็บประวัติสังกัดเดิม แต่ถ้าเริ่มงานหรือประกาศงานไปแล้ว ต้องเก็บประวัติสังกัดเดิมไว้เมื่อมีการย้าย
